# Contributing Guide

We welcome contributions to BudgetGate! 

## Code of Conduct

Please adhere to standard open source professional conduct. Be respectful of maintainers and contributors.

## Pull Request Process

1. Ensure any install or build dependencies are removed before the end of the layer when doing a build.
2. Ensure you update `README.md` and this documentation site with details of changes to the interface.
3. You may merge the Pull Request in once you have the sign-off of at least one core maintainer, or if you do not have permission to do that, you may request the reviewer to merge it for you.

## Development Standards

- **No AI filler:** Write documentation utilizing real numbers over vague claims. Use short, direct sentences.
- **Testing:** All new features must include unit tests. The GitHub Actions CI will block PRs with failing test suites.
- **Commits:** We follow Conventional Commits format (e.g., `feat(core): add multi-network support`).
